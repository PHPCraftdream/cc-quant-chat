## Decisions
- No separate lock/unlock password as in rush: the single protection for CLI admin is the owner key, password read only from the console (never argv/env) — argv would leak to agents via process list and shell history.
- Session secret = nick key (challenge + signature on every join) instead of a rotating bearer session token: nothing reusable travels or is stored besides the key.
- Node admission via one-time out-of-band invite + 6-digit verification code on both sides (against MITM of the invite); `peer add <addr> <origin>` stays an internal primitive.
- Per-chat database (node.db + chats/<id>.db), done as stage 2b after stage 2 rather than folded into it (stage 2 was already written).
- Pre-journal board/doc snapshots (import.*) stay redacted to peers — converting them to creation events would make the node forge authorship.
